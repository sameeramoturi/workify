# Workify AWS Production Deployment & Infrastructure Guide
> **Comprehensive guide for deploying Workify on Amazon Web Services (AWS)**

This guide walks you through setting up **S3**, **RDS PostgreSQL**, **IAM Roles**, **EC2**, and **CloudWatch** for production deployment.

---

## 1. Amazon S3 (Object Storage for KYC & Photos)

### A. Create the S3 Bucket
1. Open the **Amazon S3 Console** and click **Create bucket**.
2. **Bucket name**: `workify-media-storage-<your-unique-suffix>` (e.g. `workify-media-storage-prod`).
3. **AWS Region**: `ap-south-1` (Asia Pacific - Mumbai).
4. **Object Ownership**: ACLs enabled (Bucket owner preferred).
5. **Block Public Access settings**: Uncheck "Block all public access" (to allow public read access for profile pictures and work gallery photos).

### B. Configure CORS (Cross-Origin Resource Sharing)
Allow direct uploads from the web browser:
1. Go to the bucket's **Permissions** tab -> **Cross-origin resource sharing (CORS)**.
2. Click **Edit** and paste the contents of `devops/aws/s3-cors.json`:
```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "PUT", "POST", "HEAD"],
    "AllowedOrigins": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]
```

### C. Configure Public Read Policy for Public Assets
In **Bucket policy**, add permission for public read on `media/public/*` only:
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadForMedia",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::workify-media-storage-prod/media/public/*"
    }
  ]
}
```
*(Note: `media/private/kyc/*` remains strictly private and is only accessible via temporary Pre-signed URLs generated by our backend).*

## 2. Amazon RDS (Managed PostgreSQL Database)

1. Open **Amazon RDS Console** -> **Create database**.
2. **Database Engine**: PostgreSQL (version 15.x or 16.x).
3. **Template**: Free Tier (or Production).
4. **DB Instance Identifier**: `workify-db-prod`.
5. **Master username**: `workify_admin`.
6. **Master password**: `<Strong-Secure-Password>`.
7. **Instance configuration**: `db.t3.micro` or `db.t4g.micro`.
8. **Storage**: 20 GiB gp3 (Storage autoscaling enabled).
9. **Connectivity**:
   - **VPC**: Default VPC.
   - **Public access**: **No** (Strict security: Database must NOT be exposed to the internet).
   - **VPC security group**: Create new -> `workify-rds-sg`.
10. **Initial database name**: In Additional Configuration, set **Initial database name** to `workify_db`.
11. Click **Create database**.

---

## 3. Security Groups Configuration

Configure strict VPC ingress rules:

| Security Group | Inbound Rules | Source | Purpose |
| :--- | :--- | :--- | :--- |
| `workify-ec2-sg` | TCP 80 (HTTP)<br>TCP 443 (HTTPS)<br>TCP 22 (SSH) | `0.0.0.0/0`<br>`0.0.0.0/0`<br>`Your-Admin-IP/32` | Web traffic & secure SSH |
| `workify-rds-sg` | TCP 5432 (PostgreSQL) | `workify-ec2-sg` (Security Group ID) | Only EC2 can access database |

## 4. AWS IAM Role (Least-Privilege Security)

Instead of hardcoding AWS secret keys on the server, assign an IAM Role to the EC2 instance:
1. Open **AWS IAM Console** -> **Policies** -> **Create policy**.
2. Select JSON view and paste the contents of `devops/aws/iam-workify-policy.json`.
3. Name the policy: `WorkifyBackendPolicy`.
4. Go to **Roles** -> **Create role**.
5. Select **AWS service** -> **EC2**.
6. Attach `WorkifyBackendPolicy` and click **Create role**.
7. Name the role: `Workify-EC2-Role`.

## 5. Amazon EC2 Instance Launch & Setup

1. Open **Amazon EC2 Console** -> **Launch Instances**.
2. **Name**: `workify-app-server`.
3. **AMI**: Ubuntu Server 24.04 LTS (64-bit x86).
4. **Instance type**: `t3.small` (2 vCPU, 2 GiB RAM) or `t3.medium` (2 vCPU, 4 GiB RAM).
5. **Key pair**: Create or select your `.pem` key.
6. **Network settings**: Select `workify-ec2-sg`.
7. **Advanced details**:
   - **IAM instance profile**: Select `Workify-EC2-Role`.
   - **User data**: Paste the contents of `devops/aws/ec2-setup.sh`.
8. Click **Launch Instance**.

## 6. Deploying Workify on EC2

SSH into your EC2 server:
```bash
ssh -i your-key.pem ubuntu@<EC2-PUBLIC-IP>
```

Clone the repository and set up environment:
```bash
# 1. Clone repository
git clone <your-github-repo-url> workify
cd workify

# 2. Configure production environment
cp .env.example .env
nano .env
```

Update the following variables in `.env`:
```ini
DEBUG=0
ENVIRONMENT=production
SECRET_KEY=generate-a-strong-random-django-secret-key
ALLOWED_HOSTS=<EC2-PUBLIC-IP>,your-domain.com

# RDS Connection String
DATABASE_URL=postgres://workify_admin:<PASSWORD>@<RDS-ENDPOINT>:5432/workify_db

# S3 Configuration
USE_S3=1
AWS_STORAGE_BUCKET_NAME=workify-media-storage-prod
AWS_S3_REGION_NAME=ap-south-1
```

Start the production stack with Docker Compose:
```bash
cd devops/aws
docker compose -f docker-compose.prod.yml up -d --build
```

Run database migrations and seed initial data:
```bash
docker compose -f docker-compose.prod.yml exec backend python manage.py migrate
docker compose -f docker-compose.prod.yml exec backend python manage.py seed_data
```

## 7. AWS CloudWatch Monitoring & Alarms

1. Open **Amazon CloudWatch Console** -> **Alarms** -> **Create alarm**.
2. **Metric**: `EC2 > Per-Instance Metrics > CPUUtilization` (Select `workify-app-server`).
3. **Threshold**:
   - Whenever CPU is **Greater than 80%** for 2 consecutive periods of 5 minutes.
4. **Action**: Send notification to Amazon SNS Topic -> sends an email alert to your DevOps team!
5. Repeat for **StatusCheckFailed_System** to alert on hardware failure.
